# russian-text-classification

Бинарная классификация токсичных русскоязычных комментариев классическими методами
(pandas, scikit-learn, matplotlib, без нейросетей). Датасет и разбиения проекта затем
используются в `rubert-text-classification` для сравнения с RuBERT.

## Данные

**Russian Language Toxic Comments** — 14 412 комментариев с 2ch.hk и pikabu.ru,
бинарная метка `toxic` (Kaggle: `blackmoon/russian-language-toxic-comments`, версия 1,
лицензия GPL-2.0 по метаданным Kaggle API, обновлён 2019-05-12).

Kaggle требует авторизации, поэтому скрипт загрузки берёт тот же датасет из публичного
репозитория лаборатории s-nlp (Сколтех): файл `data/train/ru_toxic_dataset.csv` репозитория
[s-nlp/rudetoxifier](https://github.com/s-nlp/rudetoxifier) (лицензия репозитория MIT),
зафиксированный коммитом `aef59899fb99c8da77d4bd6dc69c9c88607e7b6e`. Этот файл — объединение двух
корпусов; Kaggle-датасет занимает в нём строки 148 775–163 186 (ровно 14 412 строк, 9 586
нетоксичных и 4 826 токсичных, как в оригинале, регистр и пунктуация сохранены).
Первые 148 775 строк — корпус с ok.ru, целиком приведённый к нижнему регистру; он не используется.

Проверка пригодности (этап 1):

- метки только 0/1, пропусков и пустых текстов нет, повторов строк источника нет;
- доля токсичных 33,5 % (соотношение 2:1) — дисбаланс умеренный;
- регистр, пунктуация и эмоджи сохранены, но в ссылках уже в источнике удалены `/` и `=`
  (например, `https: pp.userapi.com ...`);
- у 13 445 текстов есть хвостовой перевод строки — артефакт выгрузки, а не содержание;
- 8 текстов без кириллицы (ссылки, латиница) — оставлены, метки у них правдоподобны.

Вывод: датасет подходит. Он открыт, имеет проверяемый источник и лицензию, небольшой
(подходит и для дообучения RuBERT) и сохраняет регистр, который этот корпус ok.ru потерял.
Лицензия GPL-2.0 распространяется на данные; данные в репозиторий не коммитятся.

## Длины, дубликаты и разбиения (этап 2)

- Медианная длина: 117 символов у нетоксичных и 75 у токсичных; токсичные короче
  (`reports/text_analysis.json`, `reports/figures/length_by_label.png`). Самый короткий
  текст — 21 символ, видимо, это фильтр при сборе датасета.
- Точных повторов строк нет, но 257 пар текстов отличаются только хвостовым переводом строки.
  Ключ дедупликации: NFC, схлопнутые пробелы, обрезка краёв, casefold.
- **Правило противоречивых меток:** 43 пары имеют разные метки; такие группы исключаются
  целиком (86 строк), потому что метка недостоверна, а выбор одной из них был бы произвольным.
  Из остальных пар остаётся запись с наименьшим `source_row` (исключено 214 копий).
- Осталось 14 112 уникальных текстов. Стратифицированное разбиение 70/15/15, seed 42:
  train 9 878, validation 2 117, test 2 117 (доля токсичных 33,3 % в каждом).
  Разбиение делается по уникальным ключам, поэтому одинаковый текст не попадает в два разбиения.

Для повторного использования (в том числе в `rubert-text-classification`) в репозитории
лежат:

- `data/splits/split_manifest.csv` — по строке на каждую из 14 412 записей: `source_row`,
  `text_sha256` (SHA-256 исходного текста в UTF-8), `group_sha256` (SHA-256 ключа дедупликации),
  `toxic`, `split` (`train`/`validation`/`test`/`excluded`), `exclusion_reason`;
- `data/splits/data_fingerprint.json` — источник, коммит, SHA-256 файла, отпечаток содержимого,
  параметры разбиения, размеры разбиений и SHA-256 манифеста.

Загрузка разбиений с проверкой хешей: `toxic_clf.splits.load_splits()`.

## Эксперименты

Все конфигурации обучаются на train и сравниваются на validation; test не участвует
в выборе модели, параметров и порога. Параметры и метрики каждого этапа сохраняются в
`reports/experiments/<этап>.json`. Нормализация и TF-IDF входят в sklearn Pipeline и
обучаются только на train.

### Этап 3: нормализация и baseline

Нормализация минимальная: NFC, схлопывание пробелов и хвостового перевода строки.
Пунктуация, эмоджи и регистр не удаляются; регистр проверен отдельно.

| конфигурация (validation) | F1 toxic | macro-F1 | precision | recall |
|---|---|---|---|---|
| Dummy most_frequent | 0.000 | 0.400 | 0.000 | 0.000 |
| Dummy stratified | 0.337 | 0.504 | 0.339 | 0.336 |
| word TF-IDF (1-граммы) + LogReg | 0.700 | 0.794 | 0.902 | 0.572 |
| то же без приведения к нижнему регистру | 0.674 | 0.778 | 0.897 | 0.540 |

Для словных признаков приведение к нижнему регистру полезно (+0,025 F1): одно слово с
разным регистром иначе дробится на редкие признаки. Baseline очень точен, но пропускает
больше 40 % токсичных комментариев: при пороге 0,5 и без весов классов модель смещена
к мажоритарному классу.

### Этап 4: LinearSVC и словные n-граммы

Ограниченная сетка: LogReg и LinearSVC × n-граммы (1,1), (1,2), (1,3) при C=1, затем по два
дополнительных значения C для биграмм (`reports/experiments/stage4_word_models.json`).

| конфигурация (validation) | F1 toxic | macro-F1 | precision | recall |
|---|---|---|---|---|
| LogReg, 1-граммы, C=1 | 0.700 | 0.794 | 0.902 | 0.572 |
| LogReg, 1–2-граммы, C=1 | 0.666 | 0.774 | 0.916 | 0.523 |
| LogReg, 1–2-граммы, C=16 | **0.777** | 0.841 | 0.874 | 0.699 |
| LinearSVC, 1-граммы, C=1 | 0.772 | 0.836 | 0.853 | 0.705 |
| LinearSVC, 1–2-граммы, C=1 | 0.776 | 0.839 | 0.864 | 0.704 |
| LinearSVC, 1–3-граммы, C=1 | 0.775 | 0.838 | 0.860 | 0.705 |
| LinearSVC, 1–2-граммы, C=0.3 / 3 | 0.749 / 0.766 | 0.824 / 0.830 | 0.896 / 0.828 | 0.644 / 0.712 |

При C=1 логистическая регрессия слишком сильно регуляризована, и биграммы ей только мешают.
С подобранным C она догоняет LinearSVC. Биграммы дают LinearSVC небольшой прирост, а триграммы
уже ничего не добавляют. Разница между лучшими конфигурациями (0,001–0,01 F1) сравнима
с шумом на 705 токсичных примерах validation, поэтому выбор окончательной модели отложен до
этапа 6. Для LinearSVC используется только `decision_function`, вероятности он не выдаёт.

### Этап 5: символьные n-граммы, class_weight и дисбаланс

Сравнены word 1–2-граммы, `char_wb` 2–5, `char` 1–5 и объединение word+char_wb, каждая с LogReg
(C=16) и LinearSVC (C=1), без весов и с `class_weight="balanced"`
(`reports/experiments/stage5_char_models.json`).

| признаки (validation, F1 toxic) | LogReg | LogReg balanced | LinearSVC | LinearSVC balanced |
|---|---|---|---|---|
| word 1–2 | 0.777 | 0.795 | 0.776 | 0.787 |
| char_wb 2–5 | 0.840 | 0.851 | 0.846 | 0.852 |
| char 1–5 | 0.839 | **0.859** | 0.843 | 0.855 |
| word 1–2 + char_wb 2–5 | 0.837 | 0.840 | 0.831 | 0.843 |

- Символьные n-граммы дают +0,06–0,07 F1 к словным. Они устойчивы к опечаткам, маскировке
  («х...й», «бл...») и морфологии: у одного корня много словоформ.
- Объединение word+char не лучше одних символьных признаков.
- `class_weight="balanced"` поднимает recall на 3–7 п. п. ценой precision и даёт +0,01–0,02 F1.
  Average precision (качество ранжирования) при этом почти не меняется (0,929 → 0,929 у
  char_wb + LinearSVC). Значит, перевзвешивание в основном сдвигает порог: доля предсказанных
  токсичных растёт с ~0,29 до ~0,31 при истинной 0,333. Без весов модель недооценивает
  миноритарный класс.

Абляции на char_wb 2–5 + LinearSVC balanced (F1 0,852):

| вариант | F1 toxic | AP |
|---|---|---|
| без приведения к нижнему регистру | 0.859 | 0.931 |
| пунктуация и эмоджи удалены | 0.854 | 0.926 |
| word 1–2 с токенами пунктуации (вместо word 1–2: 0,787) | 0.780 | 0.863 |

Для символьных признаков сохранение регистра даёт небольшой плюс (+0,007), а удаление пунктуации
почти не влияет на F1 и немного снижает AP. Оба эффекта сравнимы с шумом, поэтому регистр и
пунктуация остаются в данных, а `lowercase` перебирается на этапе 6 как гиперпараметр.

### Этап 6: подбор на train (CV), порог и итоговая оценка

`scripts/select_model.py` (`reports/best_model.json`, `reports/experiments/stage6_cv_selection.json`):

1. 5-fold стратифицированная CV **только на train** по сетке из 24 конфигураций: char_wb 2–5 и
   char 1–5 × регистр (lowercase да/нет) × LogReg C∈{4, 16, 64} и LinearSVC C∈{0.3, 1, 3},
   все с `class_weight="balanced"` (вывод этапа 5). TF-IDF переобучается внутри каждого фолда.
2. Лучшая по средней F1 токсичного класса: **char_wb 2–5 (lowercase) + LinearSVC, C=0,3,
   balanced**, CV F1 = 0,869 ± 0,010. Следующие конфигурации отстают на 0,003–0,005, то есть
   в пределах одного стандартного отклонения.
3. Порог выбран по out-of-fold decision scores на train: −0,0857 (OOF F1 0,872). Это порог
   на `decision_function` LinearSVC, а не вероятность.
4. Модель обучена на всём train. На validation подобранный порог дал F1 0,867 против 0,864 у
   стандартного порога 0, поэтому принят по заранее заданному правилу.
5. Test использован один раз, для зафиксированной модели и порога.

| разбиение | F1 toxic | macro-F1 | precision | recall | ROC-AUC | AP | TN / FP / FN / TP |
|---|---|---|---|---|---|---|---|
| validation | 0.867 | 0.899 | 0.847 | 0.888 | 0.965 | 0.931 | 1299 / 113 / 79 / 626 |
| **test** | **0.854** | **0.889** | **0.833** | **0.877** | 0.961 | 0.927 | 1288 / 124 / 87 / 618 |

Матрицы ошибок: `reports/figures/confusion_validation.png`, `reports/figures/confusion_test.png`.
ROC-AUC и AP посчитаны по decision scores, а не по вероятностям.

Замечание: лучшее C=0,3 лежит на нижней границе сетки. Расширять сетку после того, как test
уже посмотрен, означало бы косвенно подбирать по test, поэтому это вынесено в следующие шаги.
Новую сетку нужно сравнивать по CV, а test пересчитывать только для нового зафиксированного выбора.

### Этап 7: анализ ошибок

`scripts/error_analysis.py` обучает выбранную модель на train и разбирает ошибки на
**validation** (test для анализа не используется, чтобы выводы не влияли на выбор по test).
Группы задаются грубыми эвристиками (`src/toxic_clf/errors.py`). Это инструмент подсчёта,
а не классификатор, поэтому границы групп приблизительные.

| группа (validation) | текстов | из них токсичных | FP rate | FN rate |
|---|---|---|---|---|
| все | 2117 | 705 | 0.080 | 0.112 |
| короткие (≤ 40 символов) | 301 | 159 | 0.197 | 0.038 |
| есть мат | 231 | 180 | **0.255** | 0.028 |
| есть явные оскорбления | 271 | 206 | 0.185 | 0.073 |
| маскировка / опечатки / ≥30 % слов вне словаря train | 334 | 154 | 0.167 | 0.130 |
| нет ни мата, ни явных оскорблений («скрытая агрессия») | 1680 | 378 | 0.069 | **0.164** |

Основные закономерности:

- **Мат без токсичности.** Четверть нетоксичных текстов с матом модель помечает токсичными.
  Признаки корня перевешивают функцию слова: эмоциональная окраска, пересказ, мат в
  положительном значении.
- **Скрытая агрессия.** Каждый шестой токсичный текст без явных маркеров пропущен: метафоры
  («лакей», «старый мерин»), эвфемизмы («чудак на букву М»), вежливая форма с пренебрежением.
- **Короткие тексты.** FP rate 0,20: в коротком тексте один признак (капслок, «!!!», «ты»,
  «иди») решает всё.
- **Опечатки и неологизмы.** Символьные n-граммы частично спасают, но составные оскорбления
  («консолеблядям», «свинособака») и сильно искажённый текст пропускаются.
- **Шум разметки.** Часть «ошибок» — спорные или неверные метки (агрессивные тексты с меткой 0,
  вежливый текст с меткой 1). Это ограничивает достижимое качество любой модели.

Таблица из 22 реальных FP/FN с ручными пояснениями: `reports/error_examples.csv`
(пояснения хранятся в `data/error_annotations.csv`). Все ошибки validation с оценками и
группами: `reports/validation_errors.csv`. Доли по группам: `reports/error_analysis.json`.

## Установка

```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

## Команды

```bash
python scripts/download_data.py   # загрузка, проверка SHA-256 и отпечатка
python scripts/check_data.py      # отчёт reports/data_check.json
python scripts/analyze_texts.py   # длины и дубликаты: reports/text_analysis.json
python scripts/make_splits.py     # манифест разбиений и отпечаток данных
python scripts/run_baselines.py   # этап 3: Dummy и word TF-IDF + LogReg
python scripts/compare_word_models.py  # этап 4: LinearSVC, словные n-граммы
python scripts/compare_char_models.py  # этап 5: char TF-IDF, class_weight (~2,5 мин на 4 CPU)
python scripts/select_model.py    # этап 6: CV на train, порог, итог на test (~6 мин на 4 CPU)
python scripts/error_analysis.py  # этап 7: ошибки на validation
pytest
```
